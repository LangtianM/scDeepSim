I would answer questions 1 and 3 together, since they are closely related.

The VAE in our model is mainly used for representation learning and
compression. It gives us a lower-dimensional latent space where manipulation is
easier, but direct VAE sampling is usually not accurate enough for single-cell
simulation. A standard VAE samples $z \sim \mathcal{N}(0,I)$ and then
$\hat{x} \sim p_\theta(x\mid z)$. This assumes that the decoder $p_\theta$ has
learned a good map from a Gaussian prior to the data distribution. However,
the encoded single-cell latents are much more complicated, and a solo VAE sampling does not capture the data distribution well enough. The diffusion model is added to
learn this latent distribution more accurately. This is a typical design for many generative tasks like image generation.

This also explains how our goal differs from scVI. scVI is mainly designed for
representation learning and batch correction. It can produce "posterior samples",
but these are not generated by the standard procedure described above. They are
closer to reconstruction than to genuine simulation. If $x$ is an observed
cell, the provided interface \texttt{posterior\_predictive\_sample()} samples
from $p_\theta(\hat{x}\mid x)$; that is, the observed cell is first encoded and
then decoded. This can give very realistic-looking samples, but each synthetic
cell is still anchored to a real input cell. It cannot generate new datasets of
arbitrary size without providing matching real cells.

The more relevant comparison is sampling from the prior, which means drawing
$z \sim \mathcal{N}(0,I)$ and then decoding it with the scVI decoder. scVI does
not provide a direct interface for this, but I managed to do it by calling some
internal functions. It turns out that the sample quality is much worse, as
illustrated by the UMAP below.

On the other hand, with a latent diffusion model, we can generate cells by
sampling new latents and decoding them, while achieving much better sample
quality than direct VAE prior sampling. The main advantage is that we aim for
high-quality genuine simulation while keeping latent-space controls for
signals. The disadvantage is that we need to train
and sample from an additional diffusion model, and we currently work in
log-normalized space instead of raw counts because library-size variation is hard to learn.

In short, Our model is not a replacement for scVI. scVI focuses on
representation learning and batch correction, whereas our model is more focused
on high-quality simulation with controllable latent factors.

For question 2, the latent blocks represent different semantic dimensions in the latent space.
For example, we may write
$z=(z_{\mathrm{cell}}, z_{\mathrm{batch}}, z_{\mathrm{residual}})$.
During VAE training, classification heads encourage cell-type information to
concentrate in $z_{\mathrm{cell}}$ and batch information to concentrate in
$z_{\mathrm{batch}}$. This gives us handles for intervention: for example, we
can shift only the batch block to introduce a batch effect while keeping the
cell-type block fixed.

The number of blocks is determined by the factors we want to control or
protect. In the current project, the natural choices are cell type and batch
labels. The dimension of each block is a hyperparameter. We choose it empirically by checking disentanglement and simulation quality: the
intended label should be predictable from its own block, but much less
predictable from the other blocks, while reconstruction and simulation quality
remain stable. Our current choice is 16 dimensions out of 128 total dimensions
for both the cell-type and batch blocks, which seems to work well.
